3. Жизненный цикл приложения

Последовательность действий от запуска до работы:

1
Main.kt → Application.launch()
Точка входа JVM. Вызывает JavaFX-рантайм, который создаёт экземпляр VendingApp.
2
VendingApp.start(stage)
Инициализирует primaryStage (1280×800, min 1024×700). Вызывает DatabaseConfig.init() для подключения к PostgreSQL.
3
DatabaseConfig.init()
Загружает database.properties, вызывает Database.connect() (Exposed ORM). Устанавливает JDBC-соединение с PostgreSQL через драйвер org.postgresql:42.7.1.
4
showLogin() → LoginView
Отображает экран авторизации. Подключает CSS-стили (style.css). Пользователь вводит email и пароль.
5
AuthService.login(email, password)
UserDAO.authenticate() ищет пользователя в БД, BCrypt проверяет пароль. При успехе — генерируется JWT-токен (HMAC256, 8 часов), сохраняется в SessionInfo.
6
onLoginSuccess() → showMain()
Создаёт MainView, регистрирует ThemeManager, горячие клавиши (Ctrl+Shift+T — тема, Ctrl+Shift+D — Dev-панель). Запускает NotificationService.startSimulation() для эмуляции push-уведомлений.
7
MainView → DashboardView (главная)
Первая страница — дашборд с графиками, подключёнными к реальным данным БД. Пользователь навигирует по боковому меню.

5. Слой доступа к данным (DAO)

DAO-слой реализован через Kotlin object-синглтоны. Все методы оборачиваются в transaction { } блоки ORM Exposed.

5.1. VendingMachineDAO (ключевой DAO)

Содержит самую сложную логику — агрегация для дашборда, фильтрация для монитора:

object VendingMachineDAO {
    // Полный список с resolved-именами (company, modem, inspector)
    fun getAll(): List<VendingMachine>

    // Агрегированная статистика для дашборда:
    // totalMachines, working, broken, maintenance, totalRevenue, totalCash
    fun getDashboardStats(): DashboardStats

    // CRUD
    fun create(machine: VendingMachine): Int
    fun update(machine: VendingMachine)
    fun delete(id: Int)

    // Смена статуса
    fun updateStatus(id: Int, status: String)
}

5.2. UserDAO.authenticate()

fun authenticate(email: String, password: String): User? {
    return transaction {
        val row = Users.select { Users.email eq email }.singleOrNull() ?: return@transaction null
        val hash = row[Users.passwordHash]
        if (BCrypt.checkpw(password, hash)) mapToUser(row) else null
    }
}
Паттерн: Каждый DAO самостоятельно «резолвит» связанные сущности. Например, VendingMachineDAO.getAll() дополнительно загружает companyName, modemImei и inspectorName для каждого автомата.

6. Сервисный слой (service)

🔐 AuthService
  • login(email, password) — авторизация через BCrypt + JWT
  • logout() — очистка сессии
  • generateToken(user) — JWT, HMAC256, 8ч
  • validateToken(token) — верификация JWT
  • getUserShortName() — «Иванов И.И.»
  • Хранит SessionInfo: currentUser, token, role
🔔 NotificationService
  • pushCritical/Warning/Info() — создание уведомления
  • Сохранение в БД через NotificationDAO
  • Toast-отображение с приоритетами
  • Таймауты: critical=10с, warning=7с, info=5с
  • Кнопка закрытия «✕» на каждом тосте
  • startSimulation() — эмуляция событий от ТА

Механика навигации

  1. Каждый пункт меню — Button с CSS-классом .sidebar-menu-button
  2. При клике вызывается navigateTo(viewName)
  3. Создаётся экземпляр View (lazy), его root вставляется в contentArea

9. Дашборд (главная страница)

Построен в DashboardView.kt (~358 строк). Все данные подтягиваются из реальной БД.

5 информационных блоков

📊 Эффективность сети

Процент работающих автоматов. Данные: VendingMachineDAO.getDashboardStats() → working / totalMachines × 100.

🍩 Состояние сети

PieChart (круговая диаграмма): «Работает» (зелёный), «Не работает» (красный), «На обслуживании» (жёлтый). Данные: DashboardStats.

Все графики подключены к реальным данным БД — данные тянутся из таблиц vending_machines, sales, news через DAO-слой. Тестовая база содержит 150 продаж, 25 автоматов — графики отображают реальную информацию.

12. Система push-уведомлений

ТипЦветИконкаДлительностьПример
critical #dc3545 (красный) ❌ 10 секунд «Ошибка: Нет сдачи в ТА-007»
warning #fd7e14 (оранжевый) ⚠️ 7 секунд «Внимание: Низкий запас товара A1»
info #198754 (зелёный) ℹ️ 5 секунд «Успешно: Товар выдан»

Архитектура

  1. NotificationService.push*() создаёт объект Notification
  2. Уведомление сохраняется в БД через NotificationDAO.create()
  3. Добавляется в очередь ConcurrentLinkedQueue
  4. processQueue() через Platform.runLater отображает toast
  5. Toast — VBox со стилизованным фоном, кнопкой «✕», auto-fade по таймеру
  6. Приоритет: critical > warning > info

Индикатор в top-bar

Иконка колокольчика 🔔 с красным бейджем, показывающим количество непрочитанных уведомлений (NotificationDAO.getUnreadCount()).

13. Темизация (тёмная/светлая тема)

Механизм

  1. ThemeManager.kt — синглтон (object)
  2. Хранит lightThemeProperty: SimpleBooleanProperty
  3. При toggle() переключает флаг
  4. Все зарегистрированные Scene получают/теряют CSS-класс "light-theme" на корневом элементе
  5. CSS-файл содержит ~600 строк .light-theme переопределений
// ThemeManager.kt (упрощённо)
object ThemeManager {
    val lightThemeProperty = SimpleBooleanProperty(false)

    fun toggle() {
        lightThemeProperty.value = !lightThemeProperty.value
        scenes.forEach { scene ->
            if (lightThemeProperty.value)
                scene.root.styleClass.add("light-theme")
            else
                scene.root.styleClass.remove("light-theme")
        }
    }
}

CSS-стратегия

Базовый CSS — тёмная тема. Светлая тема — каскадные переопределения через .light-theme селекторы:

/* Тёмная (по умолчанию) */
.sidebar { -fx-background-color: #0e1118; }

/* Светлая (override) */
.light-theme .sidebar { -fx-background-color: #ffffff; }

Точки переключения

  • Кнопка в сайдбаре: «☀ Светлая тема» / «🌙 Тёмная тема» — динамически обновляет иконку и текст
  • Горячая клавиша: Ctrl+Shift+T
  • Dev-панель: чекбокс внутри панели разработчика

14. Dev-панель (отладочная)

Секретная панель для быстрой отладки данных — активируется по Ctrl+Shift+D.

Функции панели

💰 Быстрая продажа

Поля: ID автомата, ID товара, количество, цена, способ оплаты. Создаёт запись в Sales через SaleDAO.create().

🔧 Смена статуса ТА

Поле ID автомата + выпадающий список статусов. Обновляет через VendingMachineDAO.updateStatus().

🎨 Переключатель темы

Чекбокс «Светлая тема» — дублирует функционал кнопки в сайдбаре.

⌨️ Справка по горячим клавишам

Отображает все доступные комбинации клавиш.

Реализация

  • Overlay: полупрозрачный фон (.dev-overlay) + панель справа (.dev-panel)
  • Появление: FadeTransition (300мс)
  • Закрытие: кнопка «✕» или повторное нажатие Ctrl+Shift+D
  • Статус-сообщения: зелёный текст при успехе операции
