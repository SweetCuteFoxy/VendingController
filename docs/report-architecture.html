3. Жизненный цикл приложения

Последовательность действий от запуска JVM до рабочего состояния приложения:

  1. Main.kt → Application.launch() — точка входа JVM. Вызывает JavaFX-рантайм, который создаёт экземпляр VendingApp.
  2. VendingApp.start(stage) — инициализирует primaryStage (1280×800, min 1024×700). Вызывает DatabaseConfig.init() для подключения к PostgreSQL.
  3. DatabaseConfig.init() — загружает database.properties, вызывает Database.connect() (Exposed ORM). Устанавливает JDBC-соединение через драйвер org.postgresql:42.7.1.
  4. showLogin() → LoginView — отображает экран авторизации. Подключает CSS-стили (style.css). Пользователь вводит email и пароль.
  5. AuthService.login(email, password) — UserDAO.authenticate() ищет пользователя в БД, BCrypt проверяет пароль. При успехе генерируется JWT-токен (HMAC256, 8 часов), сохраняется в SessionInfo.
  6. onLoginSuccess() → showMain() — создаёт MainView, регистрирует ThemeManager, горячие клавиши. Запускает NotificationService.startSimulation().
  7. MainView → DashboardView — первая страница — дашборд с графиками, подключёнными к реальным данным БД.

5. Слой доступа к данным (DAO)

DAO-слой реализован через Kotlin object-синглтоны. Все методы оборачиваются в блок transaction { } ORM Exposed.

5.1. VendingMachineDAO (ключевой DAO)

Содержит самую сложную логику — агрегация для дашборда, фильтрация для монитора:

object VendingMachineDAO {
    fun getAll(): List<VendingMachine>           // полный список с resolved-именами
    fun getDashboardStats(): DashboardStats       // агрегированная статистика
    fun create(machine: VendingMachine): Int
    fun update(machine: VendingMachine)
    fun delete(id: Int)
    fun updateStatus(id: Int, status: String)     // смена статуса
}

5.2. UserDAO.authenticate()

fun authenticate(email: String, password: String): User? {
    return transaction {
        val row = Users.select { Users.email eq email }.singleOrNull()
            ?: return@transaction null
        val hash = row[Users.passwordHash]
        if (BCrypt.checkpw(password, hash)) mapToUser(row) else null
    }
}
Примечание: Каждый DAO самостоятельно «резолвит» связанные сущности. Например, VendingMachineDAO.getAll() дополнительно загружает companyName, modemImei и inspectorName для каждого автомата.

6. Сервисный слой (service)

6.1. AuthService

  • login(email, password) — авторизация через BCrypt + JWT;
  • logout() — очистка сессии;
  • generateToken(user) — JWT, HMAC256, срок — 8 часов;
  • validateToken(token) — верификация JWT;
  • getUserShortName() — возвращает «Иванов И.И.»;
  • Хранит SessionInfo: currentUser, token, role.

6.2. NotificationService

  • pushCritical/Warning/Info() — создание уведомления;
  • Сохранение в БД через NotificationDAO;
  • Toast-отображение с приоритетами;
  • Таймауты: critical = 10 сек, warning = 7 сек, info = 5 сек;
  • Кнопка закрытия «✕» на каждом toast;
  • startSimulation() — эмуляция событий от торговых автоматов.

ТипЦветДлительностьПример сообщения

12.1. Архитектура уведомлений

  1. NotificationService.push*() создаёт объект Notification;
  2. Уведомление сохраняется в БД через NotificationDAO.create();
  3. Добавляется в очередь ConcurrentLinkedQueue;
  4. processQueue() через Platform.runLater отображает toast;
  5. Toast — VBox со стилизованным фоном, кнопкой «✕», auto-fade по таймеру;
  6. Приоритет отображения: critical > warning > info.

12.2. Индикатор в top-bar

Иконка колокольчика с красным бейджем, показывающим количество непрочитанных уведомлений (данные из NotificationDAO.getUnreadCount()).

13. Темизация (тёмная / светлая тема)

13.1. Механизм

  1. ThemeManager.kt — синглтон (Kotlin object);
  2. Хранит lightThemeProperty: SimpleBooleanProperty;
  3. При вызове toggle() переключает флаг;
  4. Все зарегистрированные Scene получают/теряют CSS-класс "light-theme" на корневом элементе;
  5. CSS-файл содержит ~600 строк переопределений для класса .light-theme.
// ThemeManager.kt (упрощённо)
object ThemeManager {
    val lightThemeProperty = SimpleBooleanProperty(false)

    fun toggle() {
        lightThemeProperty.value = !lightThemeProperty.value
        scenes.forEach { scene ->
            if (lightThemeProperty.value)
                scene.root.styleClass.add("light-theme")
            else
                scene.root.styleClass.remove("light-theme")
        }
    }
}

13.2. CSS-стратегия

Базовый CSS — тёмная тема. Светлая тема — каскадные переопределения через селекторы .light-theme:

/* Тёмная (по умолчанию) */
.sidebar { -fx-background-color: #0e1118; }

/* Светлая (override) */
.light-theme .sidebar { -fx-background-color: #ffffff; }
