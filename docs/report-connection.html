4. Инициализация подключения — DatabaseConfig

Класс DatabaseConfig — синглтон (Kotlin object), отвечающий за установление соединения с базой данных и создание таблиц при необходимости.

4.1. Метод init()

Вызывается однократно при старте приложения в методе VendingApp.start(). Последовательность действий:

  1. Загрузка конфигурации из файла database.properties;
  2. Подключение через Database.connect() из библиотеки Exposed;
  3. Логирование результата: logger.info("Database connected successfully");
  4. Установка флага isConnected = true для предотвращения повторного подключения.
// VendingApp.kt — start()
override fun start(stage: Stage) {
    DatabaseConfig.init()     // ← подключаемся к БД
    showLogin()
    primaryStage.show()
}

// DatabaseConfig.kt — ключевой фрагмент init()
Database.connect(
    url      = props.getProperty("db.url"),
    driver   = props.getProperty("db.driver", "org.postgresql.Driver"),
    user     = props.getProperty("db.user"),
    password = props.getProperty("db.password")
)

4.2. Метод createTablesIfNeeded()

Автоматически создаёт недостающие таблицы и колонки через механизм SchemaUtils.createMissingTablesAndColumns():

fun createTablesIfNeeded() {
    transaction {
        SchemaUtils.createMissingTablesAndColumns(
            Tables.Roles,       Tables.Companies,
            Tables.Users,       Tables.Modems,
            Tables.VendingMachines, Tables.Products,
            Tables.MachineProducts, Tables.Sales,
            Tables.ServiceOrders,   Tables.ServiceHistory,
            Tables.StatusHistory,   Tables.Notifications,
            Tables.News
        )
    }
}
Важно: Основная структура БД создаётся SQL-скриптом SQLCreate.sql с полным набором CHECK-ограничений. Метод createTablesIfNeeded() используется как подстраховка для автоматической миграции.

5. ORM-слой: Exposed — определение таблиц

Все таблицы определены в файле database/Tables.kt как вложенные object-ы внутри object Tables. Используется DSL-подход библиотеки Exposed:

object Tables {
    object VendingMachines : Table("vending_machines") {
        val id = integer("id").autoIncrement()
        val name = varchar("name", 255)
        val status = varchar("status", 15).default("working")
        val companyId = integer("company_id").references(Companies.id)
        val modemId = integer("modem_id").references(Modems.id).nullable()
        // ... 25+ полей
        override val primaryKey = PrimaryKey(id)
    }
}

6. Схема базы данных (SQL)

SQL-скрипт DB/SQLCreate.sql содержит полное создание схемы с CHECK-ограничениями. Ключевые ограничения для таблицы vending_machines:

CONSTRAINT check_vm_type CHECK (type IN ('cash', 'card', 'both')),
CONSTRAINT check_vm_commissioning_date CHECK (commissioning_date >= manufacture_date),
CONSTRAINT check_vm_last_verification_date CHECK (
    last_verification_date IS NULL OR
    last_verification_date BETWEEN manufacture_date AND CURRENT_DATE
),
CONSTRAINT check_vm_resource_hours CHECK (resource_hours > 0),
CONSTRAINT check_vm_service_duration CHECK (
    service_duration IS NULL OR service_duration BETWEEN 1 AND 20
),
CONSTRAINT check_vm_status CHECK (
    status IN ('working', 'broken', 'maintenance', 'offline')
),
CONSTRAINT check_vm_country CHECK (
    country IS NULL OR country IN ('Россия','Китай','Германия','Япония','США','Италия','Турция','Другая')
)

Импорт тестовых данных осуществляется скриптом DB/import_data.sql, который загружает:

  • 5 ролей, 12 компаний, 20 пользователей;
  • 30 модемов, 25 торговых автоматов, 25 товаров;
  • 60 связей «автомат–товар», 150 записей о продажах;
  • 40 заявок на обслуживание, 50 записей истории обслуживания.

7.1. Пример DAO-запроса (Exposed DSL)

// SaleDAO — получение продаж за последние 10 дней
fun getSalesLast10Days(): List<DailySales> {
    return transaction {
        val tenDaysAgo = LocalDateTime.now().minusDays(10)
        Sales.slice(Sales.saleTime, Sales.quantity.sum(), Sales.totalAmount.sum())
            .select { Sales.saleTime greaterEq tenDaysAgo }
            .groupBy(Sales.saleTime)
            .map { row ->
                DailySales(
                    date  = row[Sales.saleTime].toLocalDate(),
                    count = row[Sales.quantity.sum()] ?: 0,
                    amount = row[Sales.totalAmount.sum()] ?: BigDecimal.ZERO
                )
            }
    }
}
Примечание: Exposed автоматически использует подключение, установленное в DatabaseConfig.init(). Повторное указание подключения при каждом вызове transaction не требуется.

8. Система аутентификации (JWT + BCrypt)

Реализована в файле service/AuthService.kt как Kotlin object (синглтон).

8.1. Хеширование паролей

При регистрации пароль хешируется через BCrypt.hashpw(password, BCrypt.gensalt(10)). При авторизации — проверяется через BCrypt.checkpw() в методе UserDAO.authenticate().

8.2. JWT-токены

private const val SECRET = "VendingControllerJWTSecret2026"
private const val ISSUER = "VendingController"
private const val TOKEN_VALIDITY_MS = 8 * 60 * 60 * 1000L  // 8 часов
private val algorithm = Algorithm.HMAC256(SECRET)

fun generateToken(user: User): String {
    return JWT.create()
        .withIssuer(ISSUER)
        .withSubject(user.id.toString())
        .withClaim("email", user.email)
        .withClaim("role", user.roleId)
        .withIssuedAt(Date())
        .withExpiresAt(Date(System.currentTimeMillis() + TOKEN_VALIDITY_MS))
        .sign(algorithm)
}

8.3. Процесс авторизации

  1. Пользователь вводит email и пароль на экране LoginView;
  2. Вызывается AuthService.login(email, password), который делегирует проверку UserDAO.authenticate();
  3. BCrypt проверяет пароль: BCrypt.checkpw(password, user.passwordHash);
  4. При успехе генерируется JWT-токен (HMAC256, срок действия — 8 часов);
  5. Данные сессии сохраняются в AuthService.session: currentUser, token, role;
  6. Приложение переходит на MainView.

9. Логирование (SLF4J + Logback)

Конфигурация логирования определена в файле src/main/resources/logback.xml:

<configuration>
    <!-- Консольный вывод -->
    <appender name="STDOUT" class="ch.qos.logback.core.ConsoleAppender">
        <pattern>%d{HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
    </appender>

    <!-- Файловый вывод с ротацией -->
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>logs/vending-controller.log</file>
        <rollingPolicy class="TimeBasedRollingPolicy">
            <fileNamePattern>logs/vending-controller.%d{yyyy-MM-dd}.log</fileNamePattern>
            <maxHistory>14</maxHistory>
        </rollingPolicy>
    </appender>

    <logger name="com.vending" level="DEBUG"/>
    <logger name="org.jetbrains.exposed" level="INFO"/>
</configuration>

Логгеры используются во всех ключевых классах приложения:

private val logger = LoggerFactory.getLogger(VendingApp::class.java)
